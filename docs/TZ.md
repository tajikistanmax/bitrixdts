# Техническое задание — CMR-DTS

**Корпоративная платформа управления компанией, командой и проектами**

Версия: 1.0 · Дата: 2026-07-03 · Статус: действующее

---

## 1. Назначение и цели

CMR-DTS — единая корпоративная платформа («цифровой офис»), объединяющая управление задачами и проектами, кадровый учёт, электронный документооборот, коммуникации и аналитику. Цель — заменить разрозненные инструменты (мессенджеры, таблицы, бумажный документооборот) одной системой.

**Целевые показатели качества:**

| Показатель | Цель |
|---|---|
| Время ответа API (p95) | < 300 мс |
| Загрузка первого экрана | < 2 с |
| Одновременных пользователей на организацию | 1 000+ |
| Доступность | 99,5 % |
| Поддержка устройств | Desktop, планшет, смартфон (адаптивная вёрстка) |

## 2. Технологический стек (зафиксирован)

| Слой | Технологии |
|---|---|
| Frontend | React 19, TypeScript, Vite, Tailwind CSS v4, TanStack Query, Zustand, react-hook-form, socket.io-client |
| Backend | Node.js 20, Express 4, TypeScript, Prisma 5 |
| БД / хранилища | PostgreSQL 15, Redis (кэш, очереди), MinIO (файлы, S3-совместимое) |
| Realtime | Socket.IO |
| ИИ | Claude API (`@anthropic-ai/sdk`, модель `claude-opus-4-8`) |
| Инфраструктура | Docker Compose, Nginx, GitHub Actions CI |
| Документация API | Swagger (`/api-docs`) |

## 3. Роли и права

RBAC: роли хранятся в БД (`Role.permissions` — JSON-массив), проверка через `requireRole` / `requirePermission`.

| Роль | Права |
|---|---|
| **admin** | Всё (`*`): управление организацией, ролями, пользователями, аудит |
| **manager** | Управление задачами/проектами подразделения, согласования, отчёты по подчинённым |
| **hr** | Кадровый учёт: сотрудники, отпуска, больничные, табель, штатное расписание, зарплата |
| **employee** | Свои задачи, заявки, документы, чаты; просмотр общих разделов |

Мультитенантность: все сущности привязаны к `organizationId`; данные организаций изолированы на уровне запросов.

## 4. Функциональные требования

### 4.1 Аутентификация и безопасность ✅ (реализовано, доработки в 4.1.1)
- Вход по e-mail/паролю; JWT access (15 мин) + refresh (7 дней) с ротацией; refresh-токены в БД как sha256-хеши.
- Восстановление пароля: запрос по e-mail → письмо со ссылкой `/reset-password?token=` → установка нового пароля (страницы реализованы).
- Смена пароля в настройках. Пароли — bcrypt (12 раундов).
- Rate-limit на auth-эндпоинты; helmet, CORS, санитизация ввода, express-validator.

#### 4.1.1 Доработки (backlog)
- [ ] Минимальная длина пароля 8+ символов и на регистрации (сейчас 6).
- [ ] SSO: OAuth2 Google/Microsoft, SAML для корпоративного входа (кнопки в UI уже подготовлены).
- [ ] Двухфакторная аутентификация (TOTP).
- [ ] Журнал входов (устройство, IP) с завершением чужих сессий.

### 4.2 Сотрудники и оргструктура ✅
CRUD сотрудников, история изменений, дерево отделов, руководители, подчинённые, штатное расписание (позиции, ставки, оклады), приглашения (в т.ч. массовые).

### 4.3 Задачи и проекты ✅
Задачи (исполнитель, контролёр, соисполнители, наблюдатели, чек-листы, теги, вложения, комментарии, учёт времени, повторяющиеся задачи, шаблоны), канбан, спринты, зависимости задач + диаграмма Ганта, проекты с участниками и статистикой, мягкое удаление с восстановлением.

### 4.4 Кадровые процессы ✅
Посещаемость (check-in/out), табель (генерация из посещаемости, согласование), отпуска / больничные / командировки (заявка → согласование → подтверждение), баланс отпусков, зарплата (начисления по типам).

### 4.5 Документооборот ✅
Документы с версиями, папки (дерево), маршруты согласования (workflow по шагам), резолюции, служебные записки с регистрационными номерами, ЭЦП (поля подготовлены), файловое хранилище MinIO.

### 4.6 Коммуникации ✅
Мессенджер (каналы, личные сообщения, чаты задач) на Socket.IO, новости, объявления, корпоративная лента, встречи, календарь (типы событий: встреча/личное/праздник/дедлайн/напоминание/день рождения), уведомления (realtime + колокольчик).

### 4.7 Аналитика ✅
Дашборды (сотрудник/руководитель/директор), отчёты, KPI (метрики и значения по сотрудникам/отделам), аудит-лог всех действий.

### 4.8 Сервисы ✅
Service Desk (заявки: IT/оборудование/хозяйственные/ремонт), делегирование полномочий, рабочие пространства (обсуждения + вики), заметки, глобальный поиск, синхронизация (офлайн-очередь), автоматизация (cron: просрочки, повторы, дедлайны, дайджесты).

### 4.9 ИИ-ассистент ✅ (новый модуль)
- Endpoint `POST /api/v1/ai/chat` (авторизация обязательна, rate-limit 20 зап./мин на пользователя).
- Контекст: профиль сотрудника, активные задачи, счётчик уведомлений — ассистент отвечает по существу.
- Модель Claude `claude-opus-4-8` (настраивается `ANTHROPIC_MODEL`), ключ — `ANTHROPIC_API_KEY`; без ключа сервис отвечает 503 с понятным сообщением.
- UI: плавающая кнопка на всех страницах → чат-панель с подсказками, историей диалога в рамках сессии.

#### 4.9.1 Развитие ИИ (backlog)
- [ ] Инструменты (tool use): создание задач/заявок голосом ассистента с подтверждением пользователя.
- [ ] Суммаризация: длинных чатов, документов, ленты за неделю.
- [ ] Черновики: письма, объявления, описания задач.
- [ ] Семантический поиск по документам (embeddings + pgvector).
- [ ] Стриминг ответов (SSE) для мгновенного отклика.

### 4.10 Экран входа ✅ (обновлён)
Тёмный сплит-экран: слева форма (логин, пароль с показом, «запомнить меня», «забыли пароль», градиентная кнопка, кнопки Google/Microsoft/SSO — активируются после подключения SSO), справа витрина продукта (виджеты задач/проектов/календаря/чата, статистика, модули). Полностью адаптивен: на мобильных остаётся только форма.

## 5. Нефункциональные требования

### 5.1 Безопасность
- Все секреты — только в переменных окружения; в проде обязательна замена дефолтных значений (`JWT_*`, MinIO, Postgres, Redis). CI-проверка на плейсхолдеры.
- Тестовая подсказка аккаунта на странице входа отключается в production-сборке.
- Изоляция организаций проверяется на каждом запросе; логирование действий в AuditLog (действие, сущность, IP, user-agent).

### 5.2 Производительность
- Кэширование справочников в Redis; пагинация всех списков; lazy-загрузка страниц фронтенда (React.lazy + manualChunks).
- Индексы БД по частым выборкам (уже есть: notifications, tasks и др.).

### 5.3 UX / дизайн-система
- Единый источник токенов — `frontend/src/index.css` (`@theme`): палитры primary/ink/accent/nav, радиусы, тени.
- Запрещён хардкод `bg-white`/`bg-gray-*` — только семантические переменные (`--surface`, `--border`…), иначе ломается тёмная тема.
- UI-кит: `src/components/ui` (Button, Input, Modal, Badge, Card, Avatar, EmptyState, Spinner, PageHeader, Toast, Skeleton).
- Каркас страницы: `PageHeader` + прокручиваемый контент; загрузка → `LoadingState`, пусто → `EmptyState`.
- Тёмная тема — класс `.dark` на `<html>`, переключение в настройках и в шапке.

### 5.4 Локализация
- ✅ Инфраструктура: i18next + react-i18next, словари `frontend/src/i18n/locales/{ru,tg,en}.ts` (типизированы через `Dictionary`), язык сохраняется в `localStorage('lang')`, по умолчанию русский.
- ✅ Переведена оболочка: вход (включая витрину), восстановление/сброс пароля, сайдбар и группы навигации, шапка (поиск, меню профиля), ИИ-ассистент, настройки. Переключатель языка — на странице входа (внизу слева) и в настройках.
- [ ] Поэтапный перевод контента страниц (34 страницы): при правке страницы выносить строки в словари (`useTranslation`, ключи по разделам).

### 5.5 Тестирование
- Backend: Jest + supertest (есть), покрытие критичных модулей auth/tasks/employees ≥ 70 %.
- Frontend: Vitest + Testing Library (есть базовые), e2e Playwright (есть) — включить в CI.

## 6. Архитектура

```
frontend (React/Vite) ──HTTP/WS──> backend (Express) ──Prisma──> PostgreSQL
        │                              │                         ├─> Redis (кэш/очереди)
        │<──Socket.IO (уведомления,────┤                         ├─> MinIO (файлы)
             чат, realtime)            └──@anthropic-ai/sdk────> Claude API
```

- Backend: модульная структура `src/modules/<module>/{routes,controller,service,docs}` — 41 модуль; общий ответ `{ success, data }` (фронтенд-клиент распаковывает автоматически).
- Маршруты: `/api/v1/*` (см. `src/core/config/routes.ts`); Swagger — `/api-docs`.
- Frontend: `pages/` (35 страниц) + `services/` (по одному на модуль) + `store/` (Zustand: auth, notifications) + TanStack Query для серверных данных.

## 8. Критерии приёмки

1. `npx tsc -b && npx vite build` (frontend) и `tsc --noEmit` (backend) проходят без ошибок.
2. Полный цикл: регистрация → вход → создание задачи → согласование отпуска → уведомление → отчёт — без ошибок в консоли.
3. Восстановление пароля работает end-to-end (письмо → ссылка → новый пароль → вход).
4. ИИ-ассистент отвечает при наличии ключа и корректно сообщает о его отсутствии.
5. Тёмная тема без «белых пятен» на всех страницах.
6. e2e-набор Playwright зелёный в CI.
